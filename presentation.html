Interactive Network Error Detection & Correction Simulator

A Comprehensive Mathematical Simulation of Data Link Layer Error Control Mechanisms Integrated with Network Simulator 2 (NS-2) Physical Channel Discrete-Event Modeling

Project Scope & Technical Abstract: This project presents an end-to-end interactive simulation platform designed to model Data Link Layer error control mechanisms, physical channel noise propagation, mathematical syndrome verification, and Network Simulator 2 (NS-2) discrete-event packet loss modeling. The platform unites five foundational error control algorithms—1D Parity, 2D Parity Matrix, Hamming Code (7, 4), Internet Checksum (RFC 1071), and Cyclic Redundancy Check (CRC)—with an interactive noise injection workbench, automated Forward Error Correction (FEC), and real-time trace file analytics.

By pairing rigorous algebraic encoding with discrete-event network channel simulation, students and professors can dynamically inspect every stage of network transmission: codeword construction, bitwise noise injection, syndrome evaluation, and packet recovery across duplex communication links.

● EXECUTIVE SUMMARY

Project Motivation, Problem Statement & Objectives

Bridging theoretical Data Link Layer error control with realistic physical channel noise modeling

1. The Physical Channel Problem Statement

Transmission media impairments and silent data corruption:

In modern data communications, physical transmission channels—such as copper twisted pairs, coaxial cables, optical fibers, and free-space wireless RF media—are inherently subject to ambient physical impairments. Thermal noise, electromagnetic interference (EMI), signal attenuation, cross-talk, and transient voltage spikes cause unpredictable bit inversions (0 becoming 1 or 1 becoming 0) and multi-bit burst corruptions across transmission lines.

Without robust Data Link Layer error control, higher-layer protocols (such as TCP, IP, and application payloads) receive corrupted frames, resulting in catastrophic system crashes, corrupted database records, and critical security vulnerabilities. Furthermore, traditional academic instruction relies on static textbook formulas that fail to demonstrate how check bits interact with live channel noise, queueing delays, and packet drop events across active communication links.

2. Project Engineering Objectives

Comprehensive interactive simulation suite and goals:

The primary objective of this project is to bridge mathematical error detection theory with practical network engineering. We developed an interactive dual-mode simulation environment that implements five classical error control algorithms from first mathematical principles while linking each algorithm to a real-world Network Simulator 2 (NS-2) discrete-event transmission engine.

The platform provides complete transparency into every phase of communication: binary data encoding, redundancy overhead calculation, physical channel noise injection, receiver syndrome computation, and Forward Error Correction (FEC). Available as a Python Tkinter desktop GUI, a local HTTP server, and a cloud-hosted web application, the system allows students and professors to interactively flip bits, configure NS-2 error rates, and observe real-time packet recovery.

● SYSTEM ARCHITECTURE

End-to-End Network Transmission Pipeline

The 6 architectural stages modeling sender encoding, channel transmission, noise, and receiver recovery

Transmitter & Channel Modeling (Stages 1–3)

Message generation, mathematical encoding, and NS-2 link traversal:

The simulator is organized around an end-to-end 6-stage architectural pipeline that mirrors the actual lifecycle of a Data Link Layer frame traversing a noisy physical network. In STAGE 1 (Binary Message Input), arbitrary binary sequences or ASCII plaintext are validated, formatted, and converted into raw data vectors, with presets available for 4, 8, 12, and 16-bit word lengths.

In STAGE 2 (Redundancy Encoding & Framing), the selected mathematical algorithm computes redundant check bits—such as 1D parity bits, 2D matrix parities, power-of-two Hamming check bits, 1's complement checksums, or CRC remainder polynomials—and appends them to form the transmitted codeword. In STAGE 3 (Physical Channel & NS-2 Modeling), the codeword is transmitted across a point-to-point duplex link modeled in NS-2 (network_error_sim.tcl) with 2 Mbps bandwidth, 10 ms delay, and DropTail queue management, establishing an authentic discrete-event transmission environment.

Noise Injection, Receiver & Recovery (Stages 4–6)

Physical corruption, syndrome decoding, and autonomous error recovery:

In STAGE 4 (Channel Noise & Error Injection), transmission noise is introduced either stochastically via the NS-2 ErrorModel or interactively by allowing the user to click any bit on the canvas to invert it (0 ↔ 1), inject random single-bit noise, or simulate multi-bit burst corruptions affecting consecutive bits across the wire.

In STAGE 5 (Receiver Verification & Syndrome Computation), the receiving node recalculates parity equations, executes 1's complement addition, or carries out Modulo-2 polynomial long division on the incoming frame. Finally, in STAGE 6 (Diagnosis, Recovery & FEC), the system localizes bit errors, applies automatic Forward Error Correction where algebraically possible (as in 2D Parity and Hamming Codes), or triggers packet discard flags, displaying complete step-by-step diagnostic feedback.

● ALGORITHM 1 OF 5

1D Parity Check (Vertical Redundancy Check)

Minimal bandwidth redundancy mechanism for single-bit error detection

Mathematical Formulation & Working Mechanism

Parity generation, decision boundary, and algebraic limitations:

One-Dimensional (1D) Parity Check, traditionally referred to as Vertical Redundancy Check (VRC), represents the simplest and most lightweight error-detection mechanism in digital telecommunications. The algorithm appends a single redundant parity bit (P) to an n-bit binary data stream so that the total count of 1-bits conforms to a pre-defined parity convention. Under Even Parity, the check bit is generated as the Exclusive-OR (XOR) sum of all message bits: P = b₁ ⊕ b₂ ⊕ ... ⊕ bₙ, ensuring that the total count of 1s in the transmitted codeword is always even. Under Odd Parity, P is inverted so the total count of 1s is always odd.

At the receiving destination, the entire received codeword is XOR-summed. If the parity sum matches the expected scheme, the frame is accepted as valid. While 1D Parity requires minimal bandwidth overhead (a single bit per frame), its detection capability is strictly limited: it reliably detects all single-bit errors and any odd number of simultaneous bit flips (1, 3, 5 bits), but is completely blind to even numbers of bit flips (2, 4, 6 bits), because two inverted bits cancel each other out during binary XOR summation.

NS-2 Channel Integration & Trace Analytics

Duplex link simulation and ErrorModel packet drop verification:

In our simulation platform, the 1D Parity module is integrated with Network Simulator 2 via the network_error_sim.tcl simulation script. The transmitter node (Node 0) encapsulates the parity-encoded codeword (for example, data 11010010 with even parity bit 0 yielding codeword 110100100) into Constant Bit Rate (CBR) UDP packets and transmits them across a 2 Mbps duplex link with a 10 ms delay toward the receiver sink (Node 1).

Physical channel noise is introduced using the NS-2 ErrorModel/Uniform module, which injects packet loss and bit corruption according to a statistical packet error rate. The entire discrete-event sequence is logged into ns2/ns2_parity.tr. When NS-2 corrupts a single bit in transit, the receiver parity check fails immediately, generating an 'Error Detected' alert and discarding the packet. This confirms that 1D Parity provides 100% detection reliability for isolated single-bit transmission noise across simulated links.

● ALGORITHM 2 OF 5

2D Parity Check (Matrix Grid Localization)

Combining Longitudinal (LRC) & Vertical (VRC) Redundancy Checks for bit error correction

Matrix Structuring & Error Localization

Two-dimensional parity calculations and geometric intersection:

Two-Dimensional (2D) Parity Check significantly enhances error detection capability by organizing the raw binary message into a two-dimensional matrix of M rows and N columns. Each individual row is assigned a Longitudinal Redundancy Check (LRC) parity bit, while each column is assigned a Vertical Redundancy Check (VRC) parity bit. In addition, an overall corner parity bit is computed across all row parity bits, producing a total check bit overhead of M + N + 1 bits. This orthogonal grid structure establishes two independent parity constraints for every single data bit in the matrix.

When the frame arrives at the receiving node, parities are recalculated along both dimensions, generating a row syndrome vector and a column syndrome vector. If a single bit flip occurs at row coordinate i and column coordinate j, both the row i parity check and column j parity check fail simultaneously. The receiver determines the exact geometric intersection (i, j) of the failed parity lines, precisely localizing the corrupted bit without ambiguity.

Forward Error Correction & NS-2 Trace Integration

Autonomous 1-bit repair and multi-packet channel modeling:

The defining breakthrough of 2D Parity over 1D Parity is its capability for autonomous Forward Error Correction (FEC). Once the corrupted bit coordinate (i, j) is localized, the receiver inverts that specific bit (b[i][j] = ~b[i][j]), fully restoring the original data vector without requiring a costly packet retransmission. Additionally, 2D Parity detects up to 3 simultaneous bit errors and 100% of all burst corruptions whose length does not exceed N bits.

In our NS-2 simulation environment, the serialized 2D Parity matrix is transmitted across the duplex link between Node 0 and Node 1. The resulting trace events logged in ns2/ns2_parity2d.tr capture packet enqueue, link propagation, and receiver queueing. When channel noise corrupts a bit in transit, the receiver reconstructs the matrix grid, pinpoints the faulty row and column, and visually restores the corrupted bit in real time, demonstrating complete physical-to-link-layer error recovery.

● ALGORITHM 3 OF 5

Hamming Code (n, k) & Forward Error Correction

Power-of-two parity placement with mathematical syndrome calculation for automated recovery

Mathematical Foundation & Linear Block Theory

Richard Hamming (1950) coding theory and power-of-two bit placement:

Formulated by Richard W. Hamming in 1950, Hamming Codes are a distinguished family of linear block codes that achieve single-error correction (SEC) and double-error detection (DED). In the standard Hamming (7, 4) scheme, 4 information data bits (d₁, d₂, d₃, d₄) are combined with 3 redundant check bits (p₁, p₂, p₄) to form a 7-bit codeword. Parity bits are strictly assigned to bit positions that are powers of two (1, 2, 4, 8, ...), while data bits occupy the remaining non-power-of-two indices (3, 5, 6, 7). The required number of parity bits r for k data bits is governed by Hamming's rule: 2ʳ ≥ k + r + 1.

Each parity bit covers a specific subset of codeword bits whose binary index representation contains a 1 at that parity bit's power-of-two position. Specifically, p₁ covers bits {1, 3, 5, 7}, p₂ covers bits {2, 3, 6, 7}, and p₄ covers bits {4, 5, 6, 7}. This orthogonal assignment ensures that every bit position in the codeword is represented by a unique binary combination of parity bits, establishing a linear system of parity-check equations over GF(2).

Syndrome Decoding, FEC & NS-2 Trace Integration

Automatic single-bit correction and server memory applications:

At the destination receiver, each parity-check equation is re-evaluated to construct a 3-bit syndrome vector: S = (s₃, s₂, s₁)₂ in binary. If S = 000, the transmission is perfectly clean. If a single bit flip occurs during transit, the decimal value of the syndrome vector S directly corresponds to the exact 1-indexed position of the corrupted bit (for example, syndrome S = 101₂ = 5 indicates that bit 5 is inverted). The receiver automatically flips bit 5 back to its original state, achieving instantaneous forward error correction without retransmission.

Because Hamming codes execute in O(1) hardware cycle latency, they are ubiquitously deployed in server ECC RAM, processor caches, satellite telemetries, and RAID-2 storage systems. In our simulator, the Hamming module is bridged to NS-2 (ns2/ns2_hamming.tr). Packets subjected to simulated channel noise are captured at the receiver sink, where the 3-bit syndrome decoder identifies and repairs the inverted bit, proving empirical forward error correction across discrete-event network channels.

● ALGORITHM 4 OF 5

Internet Checksum (1's Complement Summation)

The foundational error detection mechanism powering IPv4, TCP, and UDP packet headers

Mathematical Mechanism & 1's Complement

RFC 1071 standard protocol mechanism and end-around carry addition:

The Internet Checksum is the foundational error-detection algorithm standardized in RFC 1071 and ubiquitously deployed across the core protocols of the TCP/IP suite, including IPv4 header validation, TCP segment integrity, and UDP datagram checking. The algorithm operates by segmenting the binary input stream into uniform k-bit words (typically 16-bit integers in network implementations). These words are summed together sequentially using One's Complement Arithmetic, which differs fundamentally from standard two's complement addition.

Whenever an addition produces a carry bit exceeding the k-bit boundary (an overflow), the carry bit is not discarded; instead, it is wrapped around and added back into the least significant bit (LSB), a process known as end-around carry. Once all words have been accumulated into the running sum, the bitwise one's complement (NOT operation) of the final sum is calculated, and this resulting k-bit value is transmitted as the checksum field alongside the original data payload.

Receiver Zero-Check, Limits & NS-2 Modeling

Fast router computation, protocol context, and channel loss verification:

At the destination receiver, the verification process is computationally elegant and highly optimized for router processing: the receiver sums all incoming k-bit data words plus the received checksum using one's complement addition. If no bits were corrupted during transit, the resulting sum must evaluate to all 1-bits (0xFFFF in hexadecimal), which inverts to 0x0000 (zero). Any non-zero result indicates that transmission corruption occurred, prompting the transport layer to discard the corrupted segment immediately.

Although the Internet Checksum is exceptionally fast to compute in software, it possesses recognized algorithmic limitations: it cannot detect transposed words (swapping the order of two 16-bit blocks) or compensating bit errors (where an increment in one word is mathematically cancelled by a decrement in another). In our NS-2 simulation bridge, checksum-protected packets are transmitted across the simulated link (ns2/ns2_checksum.tr). Corrupted frames trigger receiver checksum validation failures and record packet drop events at intermediate router queues.

● ALGORITHM 5 OF 5

Cyclic Redundancy Check (CRC Modulo-2 Division)

High-performance polynomial division over GF(2) utilized in Ethernet, Wi-Fi, and USB

Galois Field GF(2) Polynomial Long Division

Algebraic foundation, generator polynomials, and frame check sequence:

Cyclic Redundancy Check (CRC) is the most powerful, mathematically sophisticated, and widely deployed error-detection mechanism in modern computer networking, serving as the mandatory standard for Ethernet (IEEE 802.3), Wi-Fi (IEEE 802.11), USB, SATA, and cellular wireless links. CRC treats binary data sequences as algebraic polynomials whose coefficients belong to the Galois Field of two elements, GF(2). In GF(2) arithmetic, addition and subtraction are identical and equivalent to the bitwise Exclusive-OR (XOR) operation performed without carries or borrows.

Given an n-bit data polynomial D(x) and a predetermined (r+1)-bit generator polynomial G(x), the sender first appends r zeros to the data polynomial, shifting it by xʳ: D(x) · xʳ. The sender then executes binary long division of D(x) · xʳ by G(x) using Modulo-2 XOR operations. The resulting r-bit remainder polynomial, R(x), constitutes the Frame Check Sequence (FCS) and is appended to the message: T(x) = D(x) · xʳ ⊕ R(x). The transmitted codeword polynomial T(x) is mathematically guaranteed to be exactly divisible by G(x).

Detection Superiority, Presets & NS-2 Trace Integration

Comprehensive burst-error detection and industry standards:

The mathematical properties of CRC provide extraordinary detection power: a CRC with an r-bit generator polynomial detects 100% of all single-bit errors, 100% of all double-bit errors, 100% of all odd numbers of errors (provided G(x) contains (x+1) as a factor), and 100% of all burst error corruptions of length up to r bits. Our simulator supports key industry generator polynomials, including CRC-4 (x⁴ + x + 1), CRC-8, CRC-16-IBM, CRC-CCITT, and CRC-32 (Ethernet standard).

At the receiving node, the entire incoming codeword is divided by G(x). A remainder of zero confirms an uncorrupted frame, whereas any non-zero remainder alerts the Data Link Layer to discard the frame. In our NS-2 simulation (ns2/ns2_crc.tr), CRC-encoded frames traverse the simulated duplex link under varying ErrorModel loss rates. Corrupted frames reliably trigger non-zero syndrome remainders and register drop events in the NS-2 trace, modeling realistic Ethernet frame discards.

● SIMULATION ENGINE

Network Simulator 2 (NS-2) Architecture

Coupling physical link discrete-event simulation with Data Link Layer error control

OTcl Network Topology Configuration

Physical channel modeling in network_error_sim.tcl:

Network Simulator 2 (NS-2) is an industry-standard, object-oriented discrete-event network simulator widely utilized in telecommunication research to model network protocol dynamics, routing algorithms, and physical channel transmission impairments. NS-2 operates on a dual-language architecture: the core simulation engine and packet scheduler are written in C++ for maximum computational throughput, while simulation topology scripts, agent configurations, and event schedules are authored in Object Tcl (OTcl).

In our project, the physical channel is configured in ns2/network_error_sim.tcl. The simulation creates a point-to-point network topology consisting of a source node (Node 0) and a destination sink node (Node 1). Node 0 is configured with a UDP agent connected to a Constant Bit Rate (CBR) traffic generator transmitting 64-byte packets. Node 1 is equipped with an Agent/Null sink. The two nodes are connected via a full-duplex link configured with a bandwidth of 2.0 Mbps, a propagation delay of 10 ms, and a DropTail queue discipline.

Trace File (.tr) Parsing & Python-to-NS-2 Bridge

Real-time event analytics and WSL execution bridge:

To authentically simulate noisy physical transmission channels, the NS-2 ErrorModel/Uniform module is inserted directly into the duplex link between Node 0 and Node 1. The ErrorModel applies a configurable statistical packet loss rate, causing packets to be dropped or corrupted during transit. Dropped packets are redirected to an Agent/Null drop-target, capturing realistic channel packet drop behavior.

As packets traverse the simulated link, NS-2 outputs granular event records to standard trace files (.tr). Our Python simulation bridge (modules/ns2_bridge.py) automates the execution of NS-2 inside Windows Subsystem for Linux (WSL) and parses the 12-column event records: '+' indicates packet enqueue at Node 0, '-' indicates packet transmission onto the physical wire, 'r' represents successful packet arrival at Node 1, and 'd' denotes a packet dropped due to queue congestion or simulated channel noise. The parser computes the Packet Error Rate (PER) in real time and streams trace analytics directly to the user interface.

Multi-Dimensional Technical Trade-Off Analysis

A comprehensive engineering evaluation of error control mechanisms requires balancing four competing design constraints: transmission bandwidth overhead, computational complexity, error detection strength, and forward error correction capability. 1D Parity offers the absolute lowest bandwidth overhead (1 bit per codeword) and simplest hardware implementation (O(n) XOR gates), but provides no error correction and fails to detect even numbers of bit flips. 2D Parity introduces moderate overhead (M + N + 1 bits) but achieves single-bit forward error correction through orthogonal grid localization. Hamming Code provides optimal single-error correction (SEC) with logarithmic parity overhead (ceil(log2(n+k+1))), making it ideal for hardware-accelerated memory architectures.

The Internet Checksum requires a constant 16-bit overhead per packet and operates via simple 1's complement arithmetic (O(n) time), making it exceptionally lightweight for software execution in operating system IP stacks, though it is vulnerable to transposed and compensating bit errors. Cyclic Redundancy Check (CRC) represents the pinnacle of error detection power, guaranteeing 100% detection of all single-bit, double-bit, odd-bit, and burst errors up to r bits. Although software CRC division requires O(n · r) operations, hardware implementations execute at wire speed (O(1) cycle latency) using Linear Feedback Shift Registers (LFSR). In industry, these techniques are deployed across standard protocol layers: 1D Parity in asynchronous RS-232 serial links, 2D Parity in magnetic tape storage, Hamming Code in ECC RAM and RAID-2, Checksum in IPv4/TCP/UDP, and CRC in Ethernet IEEE 802.3 and Wi-Fi.

1. Key Accomplishments & Architecture

Project engineering deliverables:

The Interactive Network Error Detection & Correction Simulator was developed using an enterprise-grade multi-platform architecture designed for accessibility, academic demonstrations, and research experimentation.
