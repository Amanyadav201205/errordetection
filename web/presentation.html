● EXECUTIVE SUMMARY

Project Motivation & Objectives

Bridging theoretical Data Link Layer error control with realistic physical channel noise modeling

1. The Problem in Physical Transmission

Real-world transmission channel challenges:

  • Physical Noise & Attenuation: Thermal noise, cross-talk, and fading corrupt binary bits (0 ➔ 1 or 1 ➔ 0) across copper and wireless media.
  • Silent Data Corruption: Without Data Link Layer verification, corrupted packets compromise application layer payloads, files, and headers.
  • Limitations of Theory: Static textbook exercises fail to show how check bits interact with live channel noise, loss rates, and syndrome recovery.

2. Our Integrated Solution

Comprehensive interactive simulation suite:

  • 5 Core Algorithms: Full implementation of 1D Parity, 2D Parity Matrix, Hamming Code (n,k), Internet Checksum, and Cyclic Redundancy Check (CRC).
  • Network Simulator 2 (NS-2): Real discrete-event simulation via WSL with Node 0 (Tx), Node 1 (Rx), 2 Mbps link, and ErrorModel packet loss.
  • Bit-Level Error Injection: Interactive bit-flipping, random 1-bit noise, and 3-bit burst error corruption simulations.
  • Multi-Platform: Runs as Desktop GUI (Tkinter), Local Web Server (Python 3.14), and Cloud Web Application.

● ALGORITHM 1 OF 5

1D Parity Check (Even & Odd Schemes)

Minimal bandwidth redundancy mechanism for single-bit error detection

Mathematical Formulation & Working

Parity Bit Generation & Receiver Decision:

  • Concept: Appends a single check bit (P) to the data stream such that total count of 1s satisfies the chosen rule.
  • Even Parity: P = 0 if count of 1s is even; P = 1 if count of 1s is odd.
    P = b₁ ⊕ b₂ ⊕ ... ⊕ bₙ
  • Odd Parity: P = 1 if count of 1s is even; P = 0 if count of 1s is odd.
  • Detection Strength: Detects all odd numbers of bit errors (1, 3, 5...). Cannot detect even numbers of bit flips (2, 4...) because they cancel parity.

NS-2 Physical Channel Simulation

Duplex Link Modeling in network_error_sim.tcl:

  • Codeword Transmission: Transmitter (Node 0) formats frame (e.g. 11010010 + '0' = 110100100) and packetizes into UDP packets.
  • NS-2 ErrorModel: Link applies uniform loss probability. Drop events register channel corruption.
  • Trace Output: Logged in ns2/ns2_parity.tr confirming enqueue (+), drop (d), and receive (r) events.
  • Live Verification: When NS-2 corrupts a bit, receiver parity check fails instantly with 'Error Detected'.
● ALGORITHM 2 OF 5

2D Parity Check (Matrix Grid Localization)

Combining Longitudinal (LRC) & Vertical (VRC) Checks for 1-bit forward error correction

Matrix Structuring & Error Pinpointing

Row & Column Parity Intersections:

  • Grid Organization: Binary stream of length M × N is organized into an M-row by N-column rectangular grid.
  • Row Parity (LRC): Computes horizontal parity for each row i.
  • Column Parity (VRC): Computes vertical parity for each column j.
  • Intersection Localization: If bit at (Row i, Col j) flips, Row i parity FAILS and Column j parity FAILS. Their intersection (i, j) uniquely pinpoints the corrupted bit!
  • Automated Correction: The receiver flips bit (i, j) back, achieving 100% 1-bit recovery!

NS-2 Simulation & Trace Analytics

Discrete-Event Link Validation:

  • Codeword Payload: Entire (M+1) × (N+1) codeword matrix sent across NS-2 Node 0 ➔ Node 1 link.
  • Trace Output: Recorded in ns2/ns2_parity2d.tr showing packet drops from ErrorModel.
  • Recovery Demonstration: Receiver reconstructs the grid, highlights failed row and column in the visualizer, and fixes the corrupted bit.
  • Limitation: Detects multiple bit errors, but accurately flags 'Multiple Errors (Uncorrectable)' if >1 bit flips.
● ALGORITHM 3 OF 5

Hamming Code (n, k) & Forward Correction

Power-of-two parity placement with mathematical syndrome calculation for automated recovery

Mathematical Foundation & Syndrome Theory

Richard Hamming (1950) Coding Theory:

  • Check Bit Placement: For k data bits, r parity bits are placed at power-of-two positions (1, 2, 4, 8, ...) where 2ʳ ≥ k + r + 1.
  • Bit Coverage: Parity bit at position 2ⁱ checks bits whose binary index has 1 in the i-th bit position:
    P1 checks [1, 3, 5, 7, 9...], P2 checks [2, 3, 6, 7, 10...]
  • Syndrome Calculation: Receiver calculates syndrome bits: S = (sᵣ ... s₂ s₁)₂. If S = 0 => Clean. If S = D => EXACT bit at index D is corrupted!
  • Automatic Bit Flip: Bit D is inverted back to restore original message.

NS-2 Simulation & Industrial Applications

Channel Transmission & Industrial Relevance:

  • NS-2 Trace Engine: Codeword transmitted across Node 0 ➔ Node 1 duplex link with ErrorModel packet corruption.
  • Trace Output: Logged in ns2/ns2_hamming.tr.
  • Live Demonstration: When NS-2 injects channel noise, simulator calculates syndrome D, highlights bit D in yellow, and inverts it back.
  • Real-World Use: Core algorithm used in ECC RAM (Server Memory), RAID-2 arrays, and space telemetry communications.
● ALGORITHM 4 OF 5

Internet Checksum (1's Complement Sum)

The foundational error detection mechanism powering IPv4, TCP, and UDP packet headers

Mathematical Mechanism & 1's Complement

RFC 1071 Standard Protocol Implementation:

  • Block Segmentation: Binary message stream segmented into k-bit blocks (typically 4, 8, or 16 bits).
  • 1's Complement Addition: Sender adds all k-bit words together.
  • End-Around Carry: Any overflow carry bit exceeding k bits is wrapped around and added to the least significant bit (LSB).
  • Checksum Inversion: Final sum is inverted (1's complement) and appended to the payload.
  • Receiver Verification: Receiver sums all words + Checksum. If result is all 1s (complemented to 0), packet is VALID; else CORRUPTED!

NS-2 Channel Integration & Protocol Context

Network Protocol Verification:

  • NS-2 Trace Modeling: Checksum-protected frame transmitted across NS-2 duplex link.
  • Trace Output: Recorded in ns2/ns2_checksum.tr showing packet drops and delay.
  • Why Protocols Use It: Extremely fast in software with simple integer additions, requiring minimal CPU cycles in core network routers.
  • Detection Behavior: Detects all burst errors altering the arithmetic sum with zero computational bottleneck.
● ALGORITHM 5 OF 5

Cyclic Redundancy Check (CRC Modulo-2)

High-performance polynomial division over GF(2) used in Ethernet, Wi-Fi, and USB

Polynomial Division over GF(2)

Binary Modulo-2 XOR Mathematics:

  • Polynomial Representation: Data treated as polynomial M(x). Generator polynomial G(x) of degree r defines divisor.
  • Sender Encoding: 1. Multiply M(x) by 2ʳ (append r zeros). 2. Divide by G(x) using XOR operations without borrows. 3. Remainder R(x) is the CRC. Transmitted frame = M(x)·2ʳ + R(x).
  • Receiver Check: Receiver divides frame by G(x). If Remainder == 0 => Clean (Valid); else Corrupted!
  • Supported Presets: CRC-4 (10011), CRC-8 (ATM), CRC-16 (IBM), CRC-CCITT, CRC-32 (IEEE 802.3 Ethernet).

Detection Superiority & NS-2 Trace Output

Industry-Standard Error Detection Power:

  • 100% Single-Bit Errors: Any single-bit error is not divisible by G(x).
  • 100% Double-Bit Errors: Catches all double-bit errors provided G(x) does not divide (xᵏ + 1).
  • 100% Odd-Numbered Errors: Catches all odd errors if G(x) has factor (x + 1).
  • Burst Errors ≤ r Bits: Detects 100% of all bursts up to degree of G(x).
  • NS-2 Integration: Codeword transmitted in NS-2; trace logged in ns2/ns2_crc.tr with non-zero remainder on channel drop.
● SIMULATION ENGINE

Network Simulator 2 (NS-2) Architecture

Coupling physical link discrete-event simulation with Data Link Layer error control

OTcl Network Topology Configuration

Physical Channel Modeling in network_error_sim.tcl:

  • Simulator Engine: NS-2 discrete-event simulator running natively in WSL (/usr/bin/ns).
  • Transmitter Node (n0): Agent/UDP attached to Node 0 with Constant Bit Rate (CBR) traffic generator sending 64-byte packets.
  • Receiver Node (n1): Agent/Null sink attached to Node 1 acting as packet destination.
  • Duplex Link: 2.0 Mbps Bandwidth, 10 ms Delay, DropTail Queue.
  • ErrorModel Loss Module: Applied directly to link n0 ➔ n1 with uniform random loss variable ($loss_module set rate_ $err_rate).

Trace Parsing & Python-to-NS-2 Bridge

Real-Time Trace File Analytics (.tr):

  • Subprocess Bridge: Python module modules/ns2_bridge.py automates execution via WSL bash commands.
  • 12-Column Event Parser: Parses standard NS-2 event codes:
    '+' Queued | '-' Transmitted | 'd' Dropped (Noise) | 'r' Received
  • Packet Error Rate (PER): PER = (Dropped / (Received + Dropped)) × 100%.
  • NAM Animator: Outputs .nam files for network animator visualization.
